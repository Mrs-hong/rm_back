## 0. 名词速查表（先看这里，后文不再解释）

| 名词 | 通俗解释 |
|---|---|
| **T5L** | 迪文做的双核 8051 芯片，屏幕的"大脑"。分 T5L1（低分辨率）/ T5L2（高分辨率） |
| **GUI 核** | 双核之一，专职显示：按 20ms 周期把界面重绘一遍 |
| **OS 核** | 双核之二，专职服务：解析串口命令、管理变量、时钟等 |
| **DGUS** | 屏内运行的图形操作系统（DWIN Graphic Utilized Software），即 GUI 核上跑的整套系统 |
| **DGUS 周期** | GUI 核的"心跳"，固定 20ms（V7.1 手册：最短可配 15ms）。每个周期做两件事：扫描触控 + 重绘变化的控件 |
| **变量空间 / VP** | 屏内一块按"字"编址的存储区（0x0000~0xFFFF，1 字 = 2 字节，大端）。屏幕上每个控件都绑定一个 VP 地址，**改 VP 的值 = 改显示**。VP = Variable Pointer（变量指针） |
| **SP（描述指针）** | 控件属性的运行时存放地址（坐标、颜色、字号等）。改 SP = 改控件的"长相"，改 VP = 改控件的"内容" |
| **页面（Page）** | 一整屏界面 = 背景图 + 该页所有控件 + 该页所有按钮。页面 ID 就是背景图片的序号 |
| **控件（显示变量）** | 屏幕工程里的显示元素：图标、文本、数值、曲线等。每条在 14.BIN 里占 32 字节描述 |
| **触控指令** | 一个按钮的完整定义：在哪个矩形区域内、按下后切不切页、返回什么键值 |
| **13.BIN** | 触控配置文件（所有按钮的定义表），固定存放在 13 号槽位 |
| **14.BIN** | 显示变量配置文件（所有控件的定义表），固定存放在 14 号槽位 |
| **22.BIN** | 变量初始化文件：上电时把预设值写入变量空间，固定存放在 22 号槽位 |
| **ICL** | JPEG 图片库文件：把多张图片打包成一个文件。分"背景图片库"（整页大图）和"图标库"（小图标） |
| **HZK / DZK** | 点阵字库文件（ASCII / GBK 汉字）。屏幕显示文字靠它，不是靠字体文件渲染 |
| **CFG** | 硬件配置文件（T5LCFG.CFG）：波特率、CRC 开关、显示方向、触控上传开关等"出厂设置" |
| **槽位（文件 ID）** | 屏上 16MB Flash 划分成 64 个固定 256KB 的格子，编号 0~63。每个文件占一个或多个格子，"文件名前的数字 = 格子号" |
| **帧** | 串口上一次收发的完整数据包，固定以 `5A A5` 开头 |
| **0x82 / 0x83** | 两条核心串口指令：0x82 = 写变量，0x83 = 读变量 |
| **4F4B** | "OK" 的十六进制（字符 O、K）。屏幕收到写指令后回这 3 个字节的应答 |
| **键值（Key_Code）** | 按钮按下后返回的编号，主机靠它知道"哪个按钮被按了" |
| **CRC** | 循环冗余校验：给帧尾加 2 字节"防伪码"，可选功能，由 CFG 决定开不开 |

## 1. 屏幕开发者视角：从零做一个屏幕界面

### 1.1 先分清两个角色和一份"合同"

DGUS 屏的开发天然是**两个人、两条线**：

```
屏幕工程师（本节主角）                 主机工程师（第 2 章主角）
  用 DGUS PC 软件 + 图片素材              用 C/C++（或其他语言）
  产出：图片库、字库、13/14/22.BIN、CFG    产出：读写 VP 的串口程序
        ↓ SD 卡烧进屏                          ↕ 串口（UART2）
        └──────── 屏幕硬件 ────────┘
```

两人之间必须先签一份**"合同"**（其实就是一张表，越早定越少返工）：

| 合同条款 | 内容 | 谁定 |
|---|---|---|
| VP 地址表 | 每个控件用哪个 VP、什么格式（见 1.2 步骤 1 的例子） | 屏幕工程师起草，主机确认 |
| 触控键值表 | 每个按钮的 VP + 键值，主机靠它识别按键 | 同上 |
| 串口参数 | 波特率（CFG 0x0A）、CRC 开/关（CFG 0x05.7）、自动上传开/关（CFG 0x05.4） | 双方约定后烧进 CFG |
| 页面清单 | 页面 ID ↔ 界面功能对照（0 号页是哪个、1 号页是哪个…） | 屏幕工程师 |

### 1.2 开发工作流程（八步，每步有产出）

**步骤 0：硬件确认**
确认屏型号（命名规则见【开发指南】1.1，如 `DM T 80480 C 050 A 2 W TC` = 迪文/65K 色/800x480/商业级/5.0 寸/DGUS2 内核/硬件版本 2/宽温/电容触摸）、供电电压（5V/12V/24V，功率不足最常见故障是闪屏）、串口接线（CN1/CN2 插座上的 TX2/RX2/GND，TTL 电平）。

**步骤 1：变量地址规划（最重要的一步）**

变量空间分区规则（【开发指南】2.6 节）：

```
0x0000~0x0FFF   系统区：屏幕保留（页号、背光、升级接口都在这），不要放自己的数据
0x1000~0xFFFF   用户区：随便用（若 8 通道曲线全开，0x1000~0x4FFF 被曲线占用）
推荐习惯：VP 变量放 0x1000~0x7FFF，SP 描述指针放 0x8000~0xFFFF
```

做一张规划表（示例：一个空气净化器主界面）：

| VP 地址 | 用途 | 格式 | 所属页 |
|---|---|---|---|
| 0x3000 | PM2.5 数值显示 | 无符号整数 2 字节 | 1 主界面 |
| 0x3001 | 净化档位图标 | 1~12 对应图标库里第 1~12 张图 | 1 主界面 |
| 0x3010 | 时间文本 | `HH:MM:SS` + 0xFFFF 结尾 | 1 主界面 |
| 0x3100~0x3131 | 能量曲线 50 个点 | 每点 1 字 | 1 主界面 |
| 0x3383 | 任务名文本 | GBK 汉字 + 0xFFFF 结尾 | 2 设置页 |
| 0x5001 | "设置"按钮键值返回 | 按下写入 0x0001 | 1 主界面 |
| 0x5002 | "返回"按钮键值返回 | 按下写入 0x0002 | 2 设置页 |

原则：显示类放低段、触控键值类集中放一个专用段（如 0x5000 起，方便主机按地址段识别"这是按键事件"而不是数据）。

**步骤 2：界面图片制作**
- 背景图：与屏分辨率一致、24 位色 BMP/JPEG/PNG，按页面顺序命名 `00_开机页面`、`01_主界面`、`02_设置页`……（0 号页是上电默认显示页）
- 单张背景图大小限制：T5L1 ≤ 248KB（槽位 256KB，要留 ICL 文件头的位置），T5L2 ≤ 760KB。超了那张页会黑屏
- 图标：按钮的普通态/按下态各做一张，统一尺寸

**步骤 3：DGUS 软件组态（核心步骤）**
1. 新建工程，选择屏的分辨率
2. 导入背景图（每张 = 一个页面）
3. 在每页上拖控件：图标变量、数据变量显示、文本显示、实时曲线……
4. 每个控件填三要素：**变量地址（VP）、显示坐标、字库/图标库引用**
5. 画按钮区域：选择触控功能（常用"按键值返回 0x05"），填**触控区域矩形 + 键值 + 目标 VP**，需要按压换图就再配"按压效果图"
6. 点"保存"和"生成"→ 软件产出 **13.BIN（触控表）、14.BIN（显示表）、22.BIN（变量初值）**

**步骤 4：字库 / 图标库**
- 字库用迪文字库生成工具做，命名 `23_宋体24点阵GBK字库.HZK`（数字 = 槽位号）。0 号 ASCII 字库出厂已带
- 图标库：DGUS 软件把图片打包成 ICL，命名 `48_图标库.ICL`、`32_背景图片.ICL`

**步骤 5：CFG 配置**
T5LCFG.CFG 里与主机对接直接相关的位（【应用指南V71】4.1 节）：

| 地址 | 位 | 含义 | 典型值 |
|---|---|---|---|
| 0x0A | 全字节 | 波特率设置值 = 3225600 ÷ 波特率 | 115200 → 0x1C |
| 0x05.7 | 1 bit | 串口 CRC 校验开关 | 与主机一致 |
| 0x05.4 | 1 bit | **触控变量改变自动上传** | 要触控就开 |
| 0x05.5 | 1 bit | 上电加载 22.BIN 初始化变量空间 | 一般开 |
| 0x05.1~.0 | 2 bit | 上电显示方向 | 0° |
| 0x08 | 1 字节 | **背景图片库 ICL 的槽位号** | 背景库放 32 号槽就写 0x20 |

**步骤 6：SD 卡下载（烧屏）**
1. SD 卡格式化为 FAT32、4KB 扇区
2. 卡根目录建 `DWIN_SET` 文件夹，把所有文件放进去：
   ```
   DWIN_SET/
   ├── T5LCFG.CFG          ← 配置
   ├── 0_DWIN_ASC.HZK      ← 0# ASCII 字库（出厂文件，可带上）
   ├── 23_宋体24点阵GBK字库.HZK
   ├── 32_背景图片.ICL      ← 页面背景库
   ├── 48_图标库.ICL        ← 控件图标库
   ├── 13.BIN  14.BIN  22.BIN
   └── T5*.CRC             ← CRC 校验文件（可选）
   ```
3. **屏掉电 → 插卡 → 上电**：屏变蓝屏读卡，显示 `SD Card Process...END!` 表示完成
4. **掉电 → 拔卡 → 上电**：正常启动

**步骤 7：串口联调**
用 USB 转串口板 + 串口助手（SSCOM 等）手工发帧验证（帧格式见 1.5）。先发一条读当前页面：`5A A5 04 83 00 14 01`，屏应回 `5A A5 06 83 00 14 01 00 01`（当前在 1 号页）。通了再逐个验证控件 VP。

**步骤 8：定版归档**
把 `DWIN_SET` 全部文件 + VP 地址表 + 键值表归档，这就是这一代屏幕界面的"源代码"，量产直接用 SD 卡复制。

### 1.3 上电后屏幕内部的工作流程

按【开发指南】2.4 节（*"系统将调用 13.BIN 和 14.BIN，从而使人机界面得以正常运转"*）及各章节整理：

```
上电
 │
 ├─ 1. 双核复位：GUI 核启动 DGUS 系统，OS 核启动 DWIN OS
 ├─ 2. 读 CFG：拿到波特率、CRC 开关、显示方向、自动上传开关、背景库槽位号(0x08)
 ├─ 3. 检测 SD 卡：
 │      有 DWIN_SET → 进入下载流程（蓝屏）→ 写完显示 END → 重启
 │      没有         → 继续
 ├─ 4. 加载 13.BIN（触控表）、14.BIN（控件表）到工作 RAM
 ├─ 5. 若 CFG 0x05.5=1：加载 22.BIN，把预设初值写入变量空间 0x1000~0xFFFF
 ├─ 6. 从背景图片库（CFG 0x08 指向的槽）取出 0 号图片显示 ← 开机画面
 │
 └─ 7. 进入 20ms 主循环（此后永不停止）：
        每个 DGUS 周期：
        ① 扫描触控：触摸点落在当前页哪个按钮矩形里 → 执行该按钮动作
        ② 轮询控件：把 14.BIN 里当前页每个控件的 VP 读一遍，值变了就重绘
        ③ 处理串口：收到 0x82 → 改变量并回 4F4B；收到 0x83 → 回数据
        ④ 处理上传：有变量"被触控改写"且开了自动上传 → 主动发 0x83 帧给主机
```

理解这个循环就理解了 DGUS 的全部：**屏幕是一个每 20ms 自检一遍的"自动售货机"，主机和触控都只是往它的变量格里放数据/取数据，显示是它自己转出来的**。

### 1.4 对外交互：串口协议如何设计与约定

**物理层**：UART2，固定 8N1（8 数据位、无校验、1 停止位），波特率由 CFG 0x0A 决定，TTL 3.3V 电平。接线只需 TX2、RX2、GND 三根。

**帧结构**（【开发指南】4.1 节）：

```
┌────────┬──────────┬──────┬─────────────────┬─────────────┐
│ 帧头    │ 长度 LEN │ 指令 │ 数据             │ CRC（可选） │
│ 5A A5  │ 1 字节   │ 1字节│ 最多 249 字节     │ 2 字节      │
└────────┴──────────┴──────┴─────────────────┴─────────────┘
LEN = 指令 + 数据（+ 校验）的字节数；所有多字节字段大端（高位在前）
CRC-16（多项式 x16+x15+x2+1），从"指令"字节开始算，CFG 0x05.7 决定开/关
```

**日常只用两条指令**（【开发指南】4.2 节）：

```text
写变量 0x82： 5A A5 LEN 82  [VP地址2B] [数据N字节]
              应答： 5A A5 03 82 4F 4B      （"OK"）

读变量 0x83： 5A A5 04 83  [VP地址2B] [读几个字]
              应答： 5A A5 LEN 83  [VP地址2B] [字数] [数据]
```

**三条例子**（可直接在串口助手里试）：

```text
例1 写变量：把 0x3000 的数值改成 0x0064（100）
    发：5A A5 05 82 30 00 00 64
    收：5A A5 03 82 4F 4B

例2 写文本：在 0x3010 写"开机"（GBK 编码）+ 0xFFFF 结束符
    发：5A A5 08 82 30 10 BF AA BB FA FF FF
    收：5A A5 03 82 4F 4B
    注：文本控件遇到 0xFFFF 就停止显示，后面的旧残留不会画出来

例3 读变量：读当前页面号（系统变量 0x0014）
    发：5A A5 04 83 00 14 01
    收：5A A5 06 83 00 14 01 00 01   ← 最后 0x0001 = 当前在 1 号页
```

**触控上报的约定**（详见 2.2）：CFG 0x05.4=1 后，按钮按下 → 键值写入按钮配的 VP → 屏主动发一帧 0x83 格式给主机。屏幕工程师要保证**每个按钮的键值唯一**、**键值 VP 集中在一个地址段**。

**给主机同事的对接文档应包含**（模板）：VP 地址表（含格式、字节数）、键值表、波特率、CRC 开关、页面 ID 表、曲线缓冲区地址（如使用）。

### 1.5 新人排障清单

| 现象 | 按顺序检查 |
|---|---|
| 某页黑屏，其他页正常 | 该页背景图是否超 256KB（T5L1） |
| 全部黑屏 | 供电功率不足；或 ICL 槽位与 CFG 0x08 不符 |
| 文字不显示 / 乱码 | 控件 Lib_ID 指向的字库槽没烧；或字库编码不匹配；写文本时没加 0xFFFF |
| 串口无应答 | TX/RX 是否接反；波特率是否与 CFG 0x0A 一致；是否开了 CRC 而主机没算 |
| 触摸无反应 / 无上传 | 触控区域是否被别的控件遮挡；CFG 0x05.4 是否打开；功能键键码是否用了 0xFD**（它禁止上传） |
| 写了变量不刷新 | VP 是否与控件绑定一致；数据是否超出控件设定的显示范围 |

## 2. 主机（上层调用）视角：程序怎么"遥控"这块屏

### 2.0 对接前必须拿到的四样东西

1. VP 地址表（每个要操作的控件：地址、格式、字长）
2. 键值表（每个按钮：VP、键值）
3. 串口参数（波特率、CRC 开关）
4. 页面 ID 表（哪个 ID 是哪一页）

以下所有流程都假设这四样在手。参考实现见 `qifeng_framework/src/hal/screen/screen_hal.cpp`（本项目验证代码）。

### 2.1 如何控制显示

**流程 A：切页面**

```text
写系统变量 0x0084（PIC_Set 接口），第一个字 = 0x5A01（0x5A 启动 + 0x01 页面切换模式），
第二个字 = 页面 ID：
    发：5A A5 07 82 00 84 5A 01 00 01
    收：5A A5 03 82 4F 4B
内部动作：GUI 核从 CFG 0x08 指向的背景库里取 1 号图 → 铺背景 → 加载该页控件和按钮。
注意：图片 ID 不存在时指令"不生效"（不报错），所以页面 ID 必须与 ICL 实际内容一致。
```

**流程 B：更新控件数据（最常用）**

```text
直接写控件的 VP。要点三条：
1. 数值类：按控件配的数据类型发对应字节（如无符号 16 位发 2 字节大端）
2. 文本类：GBK 编码 + 0xFFFF 结尾；长度不足时靠结束符截断，无需填充
3. 频率：主机写频率不要高于 DGUS 周期（20ms）才有意义，写太快只是浪费串口
```

工程上建议主机做**差量缓存**（记住每个 VP 上次成功发送的值，相同就跳过）：串口带宽有限（115200bps ≈ 11.5KB/s），一帧 240 字节就要占 20ms 以上，没有差量的话刷一条曲线+几个文本就可能占满带宽。项目代码 `FilterUnchangedRequests()` 即此思路的验证实现。

**流程 C：改控件属性（进阶）**

若控件配置时开启了"描述指针转存"（*SP ≠ 0xFFFF），可以运行时改属性（【开发指南】2.7 节）：

```text
例：把 SP=0x8000 的控件坐标移到 (100,100)
    发：5A A5 07 82 80 01 00 64 00 64      ← 0x8000+偏移1 = 坐标字段
例：改颜色为红（RGB565 F800）
    发：5A A5 05 82 80 03 F8 00            ← 0x8000+偏移3 = 颜色字段
例：整条控件禁用：把该控件 *VP 的高字节写 0xFF
```

**如何确认"控制结果"** —— 三层确认机制，按需选用：

| 层次 | 手段 | 证明什么 | 代价 |
|---|---|---|---|
| ① 链路层 | 收到 `4F4B` 应答 | 屏收到了、变量写入了 | 零（本来就有） |
| ② 语义层 | 写成功后更新本地缓存，下次差量比对 | 数据一致性（写失败不更新缓存→自动重发） | 一点内存 |
| ③ 回读层 | 0x83 读回关键 VP / 读 0x0014 核对当前页 | 显示确实生效 | 串口带宽 |

绝大多数场景①+②足够；只有升级后初始化同步、或怀疑显示异常时才用③。

### 2.2 如何获得触控交互

四条通道，按推荐顺序：

**通道 ①：按键值自动上传（推荐，事件驱动）**

前提：屏幕工程里按钮配"按键值返回(0x05)"、CFG 0x05.4=1。

```text
流程：用户按下按钮
      → GUI 核扫描 13.BIN 命中该页按钮矩形（每 20ms 扫一次）
      → 把键值写进按钮配置的 VP（如 0x5001 = 0x0001）
      → 变量"被改变"，触发自动上传，屏主动发：
         5A A5 06 83 50 01 01 00 01     ← 格式与读应答完全相同
      → 主机按 VP 地址识别按钮（0x5001 = "设置"键），键值 0x0001
```

**几个必须知道的坑**：
- **键值写入后屏不会自动清空**（【开发指南】4.2.3 节原文）。上传由"触控写入事件"驱动——本项目产品协议（第 3 章）里每个按钮键值恒为 0x0000、每次按下都会上传，主机完全靠 VP 地址区分按钮。若联调中发现个别固件版本"同值不上传"，两个兜底：合同约定键值交替（0/1 翻转），或主机收到后回写一次
- 功能键键码 `0xFD**` 永远不上传（适合纯本地交互的按钮）；`0xFE**` 受 CFG 0x05.4 控制
- 触控指令可被主机**逐条开关**（见通道⑤），列表类界面用它做"按钮置灰"

主机接收侧的最小实现（伪代码）：

```text
收到帧 cmd==0x83：
    if addr 在触控键值区(0x5000~0x50FF):
        button = 键值表查 addr
        （可选：回写清零，防个别固件同值不重传）
        上抛事件(button, 键值)
    else:
        按普通读应答处理（配对等待中的读请求）
```

**通道 ②：按压状态同步返回（0x08）**

每个按钮可单独配置"按下/持续按压/抬起"三个阶段，任一阶段可直接把某个 VP 的数据发到串口。适合需要"按住持续调节"（如长按加减）的场景。配置在屏幕工程里做，主机只管收帧。

**通道 ③：主机轮询（兜底）**

- 读原始触摸坐标/状态：系统变量 **0x0016（TP_Status）**，4 字：
  `D7=0x5A 表示有新数据 | D6=0松开/1按下/2抬起/3按压中 | D5:D4=X坐标 | D3:D2=Y坐标`
  ```text
  发：5A A5 04 83 00 16 04
  收：5A A5 0C 83 00 16 04 5A 01 00 F0 01 40   ← 新数据/第一次按压/(240,320)
  ```
- 读当前页：0x0014。适合调试或低频场景，实时性差、耗带宽。

**通道 ④：主机主动拉取（0x0F00 变量改变指示，【开发指南】5.1 节应用示例 3）**

往 0x0F00 写 `{0x5A, VP, 字长}`，屏立即把该 VP 数据按 0x83 格式推出：

```text
发：5A A5 07 82 0F 00 5A 10 02 03      ← 拉取 0x1002 起 3 个字
收：5A A5 03 82 4F 4B
收：5A A5 0A 83 10 02 03 00 00 00 00 00 00   ← 屏主动推来的数据
```

适合"平时不上传、主机想确认时按需拉一把"的设计。

**通道 ⑤：动态开关触控（0x00B0 触控指令访问接口，【开发指南】5.1 节）**

主机可对 13.BIN 里的**任意一条触控指令**执行开启/关闭/读取/整体替换：

```text
数据格式（写到 0x00B0 起）：
  [0xB0]=0x5AA5 启动 | [0xB1]=指令所在页面ID
  [0xB2]=指令序号(高字节,DGUS软件控件视图顺序)+指令代码(低字节)
  [0xB3]=模式：0000=关闭 0001=开启 0002=读取到0xB4 0003=用0xB4数据替换
例：关闭第 0 页顺序 2 号的触控指令：
  发：5A A5 0B 82 00 B0 5A A5 00 00 02 01 00 00
  收：4F 4B
```

典型用途：列表类界面"按数据有无控制按钮可用性"——本项目产品协议正是用它实现会议卡片的按钮置灰（见 3.5 节）。

**工程纪律**：触控键值 VP 段要与主机主动读的 VP 段分开规划；升级流程期间要停触控（见 2.3 步骤 1），否则触摸产生的上传帧会混进应答流里干扰配对。

### 2.3 如何升级

**第一步：判断升什么**

| 要升的内容 | 用什么通道 | 主机能做吗 |
|---|---|---|
| 图片库/字库/配置（**页面包**，13/14/22、ICL、HZK 等） | **0x00AA 接口，串口块写** | 能（下述流程） |
| OS 核程序（DWINOS*.BIN） | 0x06 OS_Update_CMD，从变量空间搬运 | 能 |
| 底层驱动（T5L_UI/TPS04，"真正的固件"） | SD 卡 DWIN_SET 或 UART1 高速下载 | 串口 2 不能 |

主机日常说的"升级固件"通常是第一种：换界面资源包。

**第二步：页面包升级全流程（每步带帧例）**

以把新资源包写入 10 号槽（256KB = 8 个 32KB 块）为例：

```text
步骤 1  停止 DGUS 刷新 + 停 OS 核（必须！暂存区 0x8000~0xFFFF 与 SP 属性区重叠，
        不停的话 GUI 核会把升级数据当控件属性改写）
        发：5A A5 05 82 00 FC 55 AA 5A AA     ← 0xFC 第(2)模式
        （升级过程会破坏显示，本来也不需要 GUI 在跑）
        若要触摸也不响应：另发 0xFC 第(3)模式 55AA 5A5A

步骤 2  分包写入暂存区：每包 240 字节（=120 字，VP 按字编址所以地址步进 0x78）
        发：5A A5 F3 82 80 00 [240字节数据]    ← LEN = 3+240 = 243
        收：4F 4B
        循环：240B × 137 包 ≈ 32KB（一个块）

步骤 3  触发一次 32KB 块写入（0x00AA 第(2)模式）
        发：5A A5 0F 82 00 AA 5A 02 [块地址2B] 80 00 17 70 00 00 00 00
               字段含义：5A=启动 02=写32KB块模式
                         块地址 = 槽位号×8 + 块内序号（10号槽首块 = 80）
                         8000   = 数据来源（暂存区首址）
                         1770   = 延时参数 6000ms（官方调试工具同款值）
        收：4F 4B

步骤 4  轮询完成状态（读 0x00AA）
        发：5A A5 04 83 00 AA 01
        收：5A A5 06 83 00 AA 01 00 5A   ← 状态字含 5A = Flash 写入中，继续轮
            5A A5 06 83 00 AA 01 00 00   ← 含 00 = 本块完成

步骤 5  回到步骤 2 写下一块，直到 8 块全部完成（一个 256KB 槽）

步骤 6  （可选）读回校验：0x00AA 第(1)模式可把槽内容读进变量空间，
        再用 0x83 读变量与原文件比对（文档注明该模式字库 ID 范围 0x10~0xFF）

步骤 7  复位生效
        发：5A A5 07 82 00 04 55 AA 5A A5    ← 写 0x0004 = 复位命令
        屏重启，新资源生效
```

**升级期间的纪律**：不发任何普通 0x82/0x83 UI 指令；每步都等应答或超时重试（建议 3 次）；包间加小延时（验证代码用 20ms，防屏端缓冲堆积）。

### 2.4 如何升级回退

分升级对象讨论（回退能力完全不同）：

**a) OS 核升级（0x06）——屏自带回滚**

官方机制：OS 核在线更新中意外断电，**重新上电自动回滚到旧版本继续运行**（【应用指南V71】0x06 接口说明）。主机无需做任何事，重试一次升级即可。

**b) 页面包升级（0x00AA）——屏不自带，用"块 Copy"自己做**

0x00AA 还有第(3)模式：**槽位间块拷贝**，且**"Copy 中如果意外掉电中断，会在重新上电时自动继续直到完成"***（【应用指南V71】0xAA 接口）——这是官方给的双保险工具。标准做法：

```text
升级前备份（把 10 号槽整槽拷到 40 号空槽）：
    发：5A A5 07 82 00 AA 5A 03 0A 28 01 00
           字段：5A=启动 03=块Copy模式
                 0A=源槽(10)  28=目标槽(40)
                 01=拷贝 1 个 256KB 块，D3=0x00 表示整槽拷贝
    收：4F 4B，然后轮询 0x00AA 至完成（掉电也不怕，上电自动续）

升级失败 / 新包有问题 → 回退（反方向拷回来）：
    发：5A A5 07 82 00 AA 5A 03 28 0A 01 00
    收：4F 4B → 轮询完成 → 复位
```

更简单的兜底：**保留旧资源包文件，失败就重刷一遍旧包**（网络/存储成本换简单性）；有条件时 SD 卡重烧是最后手段。

**c) 变量数据（22.BIN 初始化的部分）——无需回退**

上电自动从 22.BIN 重新初始化，天然"回滚"。

### 2.5 一个完整场景把所有流程串起来

场景：主机启动后显示数据、响应用户按键、然后升级界面皮肤。

```text
[上电握手]  屏重启完成 → 主机读 0x0014 确认在 0 号页 → 发首个 UI 帧，收 4F4B
            → 链路确认 OK
[常态显示]  每 200ms：组差量包（PM2.5 值、档位、时间、曲线新点）→ 0x82 发送
            → 只发变化的字段（差量缓存）→ 收 4F4B → 更新缓存
[用户按键]  用户点"设置" → 屏发 5A A5 06 83 50 01 01 00 01
            → 主机识别 0x5001 → 回写 0 清零 → 切页到设置页（PIC_Set）→ 收 4F4B
[升级皮肤]  收到升级指令：
            1. 停触控（0xFC 模式3）→ 停 DGUS+OS（0xFC 模式2）
            2. 备份：0x00AA 模式3 把 10 号槽拷到 40 号槽，轮询完成
            3. 按第 2.3 节流程写新包到 10 号槽（分包→触发→轮询 ×8 块）
            4. 复位重启
[升级失败]  新包校验不过 → 回退：0x00AA 模式3 把 40 号槽拷回 10 号槽 → 复位
            → 回到"上电握手"，一切如初
```

## 3. 本项目产品协议实例：WLMIC_TFT 屏通信协议（把前两章串起来）

> 《WLMIC_TFT屏通信协议-260704版本》（v1.0 2026-06-02，v2.0 2026-07-04）是本项目的**真实接口合同**：会议纪要主板（SE7，运行本项目 Linux 软件）↔ TFT 触摸屏。它就是第 1.1 节说的那份"合同"的成品样子。

### 3.1 通信参数（合同的串口条款）

| 条款 | 约定 | 对应通用知识 |
|---|---|---|
| 串口模式 | N81 @115200 | CFG 0x0A（1.2 步骤 5） |
| CRC | **关闭**。协议原文：*"由于显示数据实时变化，个别数据错误影响不大，因此本通信没有启用 CRC 校验"* | CFG 0x05.7=0 |
| 帧格式 | 标准 `5A A5` 帧 | 1.4 节 |
| 键值约定 | **每按钮独立 VP、键值恒 0x0000**，主机按 VP 地址识别按钮 | 2.2 通道① |
| 命令节奏 | 连续控制命令间隔 20ms（= 一个 DGUS 周期） | 0 章名词表 |

### 3.2 页面清单（合同的页面条款）

| 页面 ID | 界面 | 切页帧（固定模板 `5AA5078200845A01+ID`） |
|---|---|---|
| 0x0001 | 待机（会议名称卡片 + AI 纪要卡片） | `5AA5078200845A010001` |
| 0x0002 | 会议中 | `5AA5078200845A010002` |
| 0x0003 | 指纹录制 | `5AA5078200845A010003` |
| 0x0004 | 系统升级 | `5AA5078200845A010004` |
| 0x0005 | 会议列表（5 张会议卡片 + 翻页/删除/下载） | `5AA5078200845A010005` |
| 0x000E~0x0011 | 下载类型二次确认页（仅文本 / 会议全部内容） | 同模板 |
| 0x0016 / 0x0017 | 取消下载确认 / SD 卡空间不足提示 | 同模板 |

项目代码对应：`addr_map.h` 的 `DisplayPage`（0x0001~0x0004，即"331 功能"首批四页）。

### 3.3 数据显示区（合同的 VP 表——会议卡片布局）

会议列表页 5 张卡片**等距布局、步长 0x2B 字**（卡片① 0x3255、② 0x3280、③ 0x32AB、④ 0x32D7……），每张卡片三个字段：

| 字段 | 相对卡片基址 | 格式 | 说明 |
|---|---|---|---|
| 会议有无 | +0 | 1 字 | 1=有会议 2=无会议（主机用它控制卡片显隐和按钮开关，见 3.5） |
| 会议名称 | +5（0x325A） | 滚动文本 | 最大 16 汉字 GBK 编码，**内容从 VP+3 开始**（滚动文本控件的格式约定） |
| 会议时间 | +0x1C（0x3271） | 定长文本 16 字节 | `2026/01/01/00:00` |

### 3.4 触控命令表（节选）与"分层交互"设计模式

触控上传帧 = 标准读应答格式 `5A A5 06 83 [按钮VP] 01 00 00`：

| 按钮 | 上传帧 | VP | 主机动作 |
|---|---|---|---|
| 待机页【查看详情】 | `5AA506833367010000` | 0x3367 | 进会议列表、刷新数据 |
| 会议列表【返回首页】 | `5AA506833365010000` | 0x3365 | 回待机页、刷新 |
| 首页/上一页/下一页/尾页 | `...3357 / 335B / 335C / 335D...` | 0x3357+ | 翻页重查列表 |
| 【取消】（所有二次确认页共用） | `5AA506833359010000` | 0x3359 | 刷新列表数据 |
| 删除确认 ①~⑤ | `...333C / 3E / 40 / 42 / 44...` | 0x333C+ | 删除全部/对应会议 |
| 下载确认（仅文本 / 全部内容） | `...3346~3355...` | 0x3346+ | 触发对应类型下载 |

**分层交互设计模式（本协议最值得学习的一点）**：删除/下载都做成两跳——一级按钮只做**屏内切页**（`Pic_Next` 跳到二次确认页，协议中标注"对应的界面（不发送给后端）"），只有**确认键**才发上传帧给主机。防误触完全放在屏内交互层，主机协议保持极简。

### 3.5 动态开关触控（0x00B0 接口的实战用法）

会议列表每次刷新数据时，"数据有无"决定哪些卡片按钮可用。主机对每条触控指令下发开关命令（即 2.2 通道⑤）：

```text
例：关闭会议列表页（页5）卡片①的按钮（该页触控指令序号 0x02）：
    发：5AA50B8200B05AA5000502050000
    开启则末字改 0001：5AA50B8200B05AA5000502050001
协议文档约定：
  - "指令序号"来自 DGUS 软件控件视图顺序（0=全部删除、2~9=卡片①~⑤按钮与
    删除icon、14=格式化…），GUI 工程师必须把它写进合同
  - 连续下发多条时每条间隔 20ms；也可先读 0xB0（5AA5048300B001），
    为 0 表示上一条已处理完，再发下一条
```

这解决了"按钮置灰"的老问题：不重烧工程、不改显示，纯主机侧控制触控可用性。

### 3.6 对本项目代码的验证意义

- `DisplayPage` 0x0001~0x0004 与协议页面表一致（331 功能阶段）
- CRC 不启用 ↔ `diwen_protocol.cpp` 无校验实现
- 触控 VP 段（0x3330~0x3367）与显示 VP 段（0x3000~0x32xx）相邻但可按地址段区分——2.2 章"地址段隔离"的实际形态
- 协议含大量触控命令，而 `screen_hal.cpp OnReceiveData()` 尚无触控分发——即第 1 章分析指出的扩展点，落地时按 2.2 伪代码实现即可
